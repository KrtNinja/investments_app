# Требования к странице учёта портфеля

Что страница показывает и как считает. По этому документу страницу можно пересобрать с нуля
на любом стеке. Текущая реализация: `index.html`, `src/web/`, расчёты — `src/core/model.js`.
Если код и документ расходятся, правится то, что неверно; намеренное отличие — фиксируется здесь.

## 1. Принципы

1. **Все цифры только из данных.** В разметке нет чисел; константы допустимы лишь как часть формул (например, порог 2,4 млн ₽ для ставки 15%).
2. **Источник правды — CSV в репозитории с данными** (формат — в его `AGENTS.md`). Страница читает их через GitHub API и пишет туда же: каждое изменение — один атомарный коммит. Если данные поменялись после загрузки, запись отклоняется и предлагается «Обновить».
3. **Формулы отдельно от разметки.** Все расчёты — чистые функции `src/core/model.js`, общие для страницы и `cli/invest.js`, поэтому цифры на странице и в CLI совпадают. В коде страницы формулы не дублировать.
4. **Один код на все портфели.** Портфель выбирается из `portfolios.csv`, меняются только данные.
5. **Интерфейс на русском.** Числа по-русски: пробел — разделитель разрядов, запятая — десятичная.
6. **Сеть — только GitHub API и ISS Мосбиржи** (кнопка «Актуализировать цены»). Никаких других серверов, токен хранится только в браузере.

## 2. Входные данные

| Файл | Что это |
|---|---|
| `portfolios.csv` | Реестр портфелей: id, название, брокер |
| `portfolios/<id>/operations.csv` | Журнал операций |
| `portfolios/<id>/securities.csv` | Справочник бумаг с ценой и НКД за 1 шт |
| `portfolios/<id>/settings.csv` | Пары `key,value` |
| `portfolios/<id>/target_classes.csv` | Целевые доли классов |
| `portfolios/<id>/target_issues.csv` | Целевые доли выпусков облигаций |
| `portfolios/<id>/history.csv` | Снимки капитала |

Значения приходят строками, функции модели сами приводят их к числам.

## 3. Слой расчётов

Цепочка (стрелка — «нужно для»):

```
operations ───────────────► flows
flows, securities ────────► positions
flows, positions ─────────► capital                 (1 запись)
positions, capital, target_classes ► classes
positions, capital, target_classes, target_issues, settings ► issues
issues, capital, target_classes ► groups
positions, capital, issues, settings ► goal         (1 запись)
flows, settings ──────────► taxes                   (запись на год)
flows, positions, target_classes, target_issues ► checks
```

Поля, на которые опирается страница:

- **flows:** `n, date, type, ticker, name, qty, amount, aci, fee, tax, price_per, flow, dqty, to_card, cost_sold, comment`.
- **positions:** `ticker, name, class, isin, qty, price, aci, value, invested, received, income, result, result_pct, share, coupon_year`.
- **capital:** `deposits, withdrawals, net, cash, securities, capital, card_income, reinvest, growth, growth_pct, coupons, dividends, taxes, fees`.
- **classes:** `class, target, value, share, deviation, to_buy`.
- **issues:** `issue, group, decision, target, goal, value, share, deviation, to_buy, unit_price, buy_qty, coupon_year, coupon_yield`.
- **groups:** `group, target, goal, value, share, deviation, to_buy`.
- **goal:** `target_monthly_income, target_yield, target_sum, progress, income_year, income_month, income_share, current_yield, current_yield_net, issues_total`.
- **taxes:** `year, coupons, aci_paid, aci_got, trades, base, tax_main, dividends, tax_div, total, withheld, due`.
- **checks:** `kind, item, detail`.

Формулы словами — в `docs/reference.md` репозитория с данными.

## 4. Структура страницы

Одна страница с разделами и оглавлением-якорями: `#svodka`, `#bumagi`, `#struktura`, `#nalogi`, `#operacii`, `#cel`.
Ссылка с якорем открывает страницу на нужном разделе.

### Шапка

Выбор портфеля, источник данных, кнопки «Обновить», «Актуализировать цены», «Внести операцию», «Выйти».
Под шапкой — название портфеля, брокер и тариф.

### Сводка (`#svodka`)

1. **Главная строка:** сколько купоны приносят в месяц на руки и какая это доля от цели (`goal.income_month`, `goal.income_share`, `goal.target_monthly_income`) — с полосой прогресса.
2. **Ключевые цифры:** Капитал (с датой цен), Чистые вложения, Прирост (₽ и % к чистым вложениям, цвет по знаку), Купонная доходность (`goal.current_yield`, 2 знака; под ней — на руки `goal.current_yield_net` и купоны в год `goal.income_year`), Свободные деньги, Нужно капитала для цели (с прогрессом).
   Полный список, доступный хотя бы по раскрытию: Пополнено, Выведено, Чистые вложения, Деньги на счёте, Стоимость бумаг, **Капитал**, Доход, ушедший на карту, Реинвест с карты, **Прирост**, Прирост %, Купоны (до налога), Дивиденды (до налога), Налоги, Комиссии, Прогресс к цели, Купоны в год (до налога), Купонная доходность (до налога), Купонная доходность на руки, Купоны в месяц на руки, Доля от целевого потока. Рядом — формула прироста: капитал + доход на карту − реинвест с карты − чистые вложения.
3. **Что проверить** — список `checks`: метка `kind` цветом предупреждения, затем «item — detail». Пусто — блок не показывается или «Замечаний нет». Подсказка: деньги на счёте сверять с приложением брокера.
4. **История капитала** по `history.csv`: линии «Чистые вложения» и «Капитал» по датам; ось Y по диапазону данных (не от 0 — иначе разница в доли процента не видна), подписи в ₽ без копеек, подсказка с датой, вложениями, капиталом и приростом. При одном снимке — текст вместо графика. Под графиком или по раскрытию — таблица: Дата, Чистые вложения, Капитал, Прирост (цвет по знаку).

### Бумаги (`#bumagi`)

Таблица `positions`: Тикер, Название, Кол-во, Цена, НКД, Стоимость, Вложено, Получено, Купоны, Результат, Результат %, Доля, Купон в год; строка «Итого».
Сначала бумаги с остатком, затем проданные — серым (или скрыты под раскрытием). Результат и Результат % — цвет по знаку.
Пояснение: цена и НКД за 1 шт; результат = рыночная стоимость + всё полученное (продажи, купоны на счёт и на карту) − всё потраченное на покупки.

### Структура (`#struktura`)

1. **Доли выпусков: сейчас и цель** — горизонтальные полосы по `issues`: полоса = текущая доля, черта другого цвета = цель, справа подпись текущей доли. Подсказка: выпуск, сейчас (% и ₽), цель (% и ₽), докупить ₽.
2. **Ребалансировка по выпускам** — таблица `issues`: Выпуск, Решение, Цель (доля и ₽), Сейчас (₽ и доля), Отклонение, Докупить (+) / лишнее (−), Цена с НКД, Докупить шт, Купон в год, Купон к цене. Пояснения: минус у «Держать» значит «не докупать», а не «продавать»; штуки с учётом комиссии `fee_rate`. Ниже — купонная доходность целевого набора `goal.target_yield`.
3. Рядом: **По группам** (`groups`: Группа, Цель, Сейчас, Отклонение, Докупить ₽) и **По классам активов** (`classes`: Класс, Цель, Сейчас ₽, Сейчас, Докупить/лишнее; классы с нулевой целью и нулевой стоимостью не показываются или серым).

### Налоги (`#nalogi`)

Таблица `taxes` по годам: Год, Купоны, − НКД уплаченный, + НКД полученный, + Сделки, База, Налог, Дивиденды, Налог с дивидендов, Итого налог, Удержано, Доплатить (+) / вернуть (−). Колонки дивидендов можно скрывать, если дивидендов нет.
Пояснения: купоны и сделки — одна база, дивиденды отдельно; брокер считает сам, здесь проверка и прогноз; уплаченный НКД вычитается в год покупки; 13% / 15% свыше 2,4 млн; льгота 3+ года и ИИС не учитываются; необлагаемый лимит процентов — только для вкладов.

### Операции (`#operacii`)

Таблица `flows`, **новые сверху**: №, Дата, Тип, Бумага, Кол-во, Сумма, НКД, Комиссия, Налог, Цена за шт, Поток по счёту (цвет по знаку), На карту, Себестоимость проданного, Комментарий (переносится, приглушённым цветом). Нулевые НКД/комиссия/налог/на карту — пустые ячейки.
Пояснение: сумма без НКД, комиссии и налога; поток — изменение денег на счёте; каждое изменение — коммит, его можно откатить.

**Ввод операции** — форма с полями по колонкам `operations.csv`. Для бумаги, которой нет в справочнике, — добавить её строку в `securities.csv` (название, ISIN, класс, купон в год). Поле комментария — технические пометки (откуда цифры); мотивы сделок ведутся в `docs/decisions.md` репозитория с данными, не в комментарии.
**Удаление операции** — с подтверждением, отдельным коммитом.

### Цель и стратегия (`#cel`)

1. «Название — значение»: Цель, Целевой поток в месяц, **Целевая сумма**, Прогресс, Срок, Плановое пополнение, Допустимая просадка («не задана», если пусто), Стратегия, Правила ребалансировки, Что делать с купонами, Ограничения. Длинный текст переносится. Рядом — формула целевой суммы: целевой поток × 12 / (1 − налог) / купонная доходность целевого набора.
2. **Целевые доли классов** — `target_classes.csv`: Класс, Доля, Комментарий; пометка «сумма должна быть 100%».
3. **Целевые доли по выпускам** — `target_issues.csv`: Выпуск, ISIN, Группа, Срок, Доля, Решение, Купон %, Выплат в год, Погашение, Комментарий; над таблицей — `settings.issues_source`.

## 5. Форматирование

| Что | Формат | Пример |
|---|---|---|
| Деньги в таблицах | 2 знака, пробел в разрядах | `16 159,90` |
| Деньги в крупных цифрах сводки | без копеек, « ₽» | `60 000 ₽` |
| Доли и проценты | × 100, 1 знак (доходности и прирост в процентах — 2), «%» | `15,0%` |
| Отклонение долей | в процентных пунктах | `+2,5 п.п.` |
| Комиссия `fee_rate` | 4 знака | `0,0685%` |
| Даты | `ДД.ММ.ГГГГ` | `23.10.2026` |
| Цена за шт в операциях | до 4 знаков | `807,995` |
| Знак | > 0,004 — «плюс»-цвет, < −0,004 — «минус»-цвет, иначе обычный | |
| Пустое значение | пустая ячейка (не 0, не NaN) | |

Числа в таблицах выровнены вправо, цифры моноширинные (`tabular-nums`), текстовые колонки — влево. Заголовки длинных таблиц «прилипают» при прокрутке; широкие таблицы прокручиваются внутри своего блока, а не всей страницей.

## 6. Внешний вид

- Все цвета, шрифты и размеры — CSS-переменными в начале `src/web/styles.css`; в правилах и SVG только `var(--…)`. Новый цвет — новой переменной.
- Светлая и тёмная темы: тёмная включается по `prefers-color-scheme: dark`; обе читаются.
- Смысловые цвета: доход/плюс, убыток/минус, цель (черта на полосах), предупреждение («Что проверить»). На графике истории «Капитал» и «Чистые вложения» разного цвета, с легендой.
- Крупные числа и заголовки — шрифтом с засечками, остальное — без засечек.
- Страница читается на ширине ~400 px: без фиксированных ширин и горизонтальной прокрутки страницы; графики строятся от ширины контейнера и перерисовываются при её изменении; подсказки не выходят за край.
- Пока данные грузятся — заглушки, при ошибке загрузки — понятное сообщение, старые цифры и графики не остаются.

## 7. Безопасность

- Значения из CSV — недоверенный текст: выводить через `textContent`/создание узлов, никогда через `innerHTML`.
- Content-Security-Policy ограничивает сеть GitHub API, ISS Мосбиржи и шрифтами; внешних скриптов нет.
- Токен — fine-grained, только на репозиторий с данными, Contents: Read and write; хранится в `localStorage` или до закрытия вкладки.

## 8. Приёмка

На тех же данных:

1. Капитал, прирост, чистые вложения, деньги на счёте, купоны в месяц, целевая сумма и налог к доплате по годам совпадают с `node cli/invest.js summary <id> --json` до копейки. Контрольная точка — последняя строка `history.csv` портфеля: чистые вложения, капитал и прирост на ту же дату цен должны совпасть.
2. Нигде нет `NaN`, `undefined`, `Infinity`.
3. Все разделы на месте, ссылка с якорем открывает нужный.
4. «Что проверить» показывает те же замечания, что `checks` в CLI.
5. На ширине 400 px нет горизонтальной прокрутки страницы.
6. Светлая и тёмная темы читаются.
7. Внесение и удаление операции дают ровно один коммит в репозитории с данными и проходят `scripts/validate.py` там.
